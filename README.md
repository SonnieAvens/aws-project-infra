# AWS Infrastructure via Terraform + GitHub Actions

Provisions in **us-east-1**:
- VPC with public + private subnets across 2 AZs, IGW, NAT Gateway
- EC2 (Amazon Linux 2023, t3.micro) in public subnet
- RDS PostgreSQL 17 (db.t3.micro) in private subnet — credentials stored in Secrets Manager
- Lambda function that lists all AWS resources in the account

## One-Time Setup

### 1. Create GitHub Repository

Push this code to `https://github.com/savenbuan2025/<repo-name>`:

```bash
git init
git add .
git commit -m "Initial infrastructure"
git remote add origin https://github.com/savenbuan2025/<repo-name>.git
git push -u origin main
```

### 2. Create AWS IAM User for GitHub Actions

In AWS Console → IAM → Users → Create user:
- Name: `github-actions-terraform`
- Attach policies: `AdministratorAccess` (or a scoped policy for your resources)
- Create Access Key → save **Access Key ID** and **Secret Access Key**

### 3. Add GitHub Secrets

Go to your GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret Name            | Value                                      |
|------------------------|--------------------------------------------|
| `AWS_ACCESS_KEY_ID`    | IAM user access key ID                     |
| `AWS_SECRET_ACCESS_KEY`| IAM user secret access key                 |
| `TF_STATE_BUCKET`      | A globally unique S3 bucket name, e.g. `myproject-tfstate-123456` |

> **Note:** No `DB_PASSWORD` secret needed. Terraform auto-generates a 32-character password and stores it in AWS Secrets Manager.

### 4. Push to main

The pipeline runs automatically on every push to `main`:
- **Pull Requests** → runs `plan` only (no apply)
- **Push to main** → runs `plan` then `apply`

## RDS Credentials (Secrets Manager)

Terraform stores the RDS credentials automatically in AWS Secrets Manager at:

```
myproject/rds/credentials
```

The secret contains a JSON object:

```json
{
  "username": "dbadmin",
  "password": "<auto-generated>",
  "host":     "<rds-endpoint>",
  "port":     5432,
  "dbname":   "appdb",
  "engine":   "postgres"
}
```

**Retrieve credentials via AWS CLI:**

```bash
aws secretsmanager get-secret-value \
  --secret-id myproject/rds/credentials \
  --region us-east-1 \
  --query SecretString \
  --output text | python3 -m json.tool
```

**Retrieve credentials in Python (e.g. from Lambda or EC2):**

```python
import boto3, json

client = boto3.client("secretsmanager", region_name="us-east-1")
secret = json.loads(client.get_secret_value(SecretId="myproject/rds/credentials")["SecretString"])

host     = secret["host"]
port     = secret["port"]
dbname   = secret["dbname"]
username = secret["username"]
password = secret["password"]
```

The Lambda function already has scoped IAM permission (`GetSecretValue`) to this secret and receives its ARN via the `DB_SECRET_ARN` environment variable.

## Useful Commands (local)

```bash
# Init with your state bucket
terraform -chdir=terraform init \
  -backend-config="bucket=YOUR_BUCKET" \
  -backend-config="key=terraform.tfstate" \
  -backend-config="region=us-east-1"

# Plan
terraform -chdir=terraform plan -var="aws_region=us-east-1"

# Apply
terraform -chdir=terraform apply -var="aws_region=us-east-1"

# Destroy
terraform -chdir=terraform destroy -var="aws_region=us-east-1"
```

## Notes

- **RDS PostgreSQL version**: If `17.2` is unavailable, run:
  ```bash
  aws rds describe-db-engine-versions --engine postgres \
    --query "DBEngineVersions[?starts_with(EngineVersion,'17')].EngineVersion"
  ```
  Then update `engine_version` in `terraform/rds.tf`.
- **SSH access**: EC2 SG currently allows `0.0.0.0/0` on port 22 — restrict to your IP in production.
- **NAT Gateway** incurs hourly + data transfer costs (~$32/month). Remove it if Lambda doesn't need internet.
